# SpectraSherpa 0.6.4

**Unreleased candidate.** These notes describe the changes prepared for 0.6.4,
not a published package. The version bump, final qualification and release
approval remain pending. No PyPI upload, release tag, desktop installer or
production deployment is implied.

## Work with data

- [My Dataset portfolios](../workflows/data-import.md#build-a-portfolio-in-my-dataset)
  retain named selections, targets, groups and reviewed inclusion choices for
  reuse across workflow sheets. Sample identity is separate from editable labels.
- [Multi-well](../workflows/multi-well.md) supports 6-, 12-, 24-, 48-, 96-, 384-
  and 1536-well formats. Large plates pan without shrinking labels; acquisition
  plans and published measured-sample versions remain separate.
- Import, Upload, Library, Synthesis and Multi-well lead to My Dataset before
  Workflow. Storage recovery is under Settings.
- Data Story uses parsed source facts and distinguishes acquisition settings
  from synthesis recipes. Starter, Data Story and chat can use an externally
  supplied API key in local OSS; the selected provider's policies and charges apply.

## Analyze and inspect

- New PCA starters fit scaling inside PCA and each eligible validation fold.
  The preprocessing starter applies recorded sample inclusion through Filter.
  Existing workflows are not silently rewritten.
- Quick Plot and Detailed View share scientific projections and component
  controls. Tables and plots retain declared axes, units and population context;
  sampled or capped displays carry a visible **Subset** indicator.
- Runs uses consistent Summary, Results and Validation sections. Inspect links
  to the produced model; promotion review belongs under Models.
- Reports retain essential scientific qualifiers. Prepared exports distinguish
  plain CSV from portable CSV, support JSON, and package all processed spectra
  as individual JCAMP-DX files in a ZIP when JDX is selected.

## Reliability and presentation

Shared theme tokens cover controls, plots and offline reports. Categorical
palettes honor accessibility preferences; legacy server-built figures with
recorded explicit colors keep those colors. Scoped requests reject late replies
without clearing the workspace during same-account token renewal. Generated
API types, node reference tables and help-link checks reduce documentation drift.

Dependency security updates cover Python, frontend and optional tooling without
changing the qualified scikit-learn or SpectroChemPy scientific-runtime pins.
Source-level desktop dependency checks do not resume desktop packaging.

## Upgrading from 0.6.0–0.6.3

Back up the data directory and export important projects before upgrading.
Follow [Migrate to 0.6](../onboarding/migrate-to-0.6.md) for installation and
scientific-contract boundaries; install an exact source candidate for testing,
not a presumed 0.6.4 package.

- Review the intervening [0.6.1](0.6.1.md), [0.6.2](0.6.2.md) and
  [0.6.3](0.6.3.md) notes when upgrading directly from the earlier PyPI package.
  Older KNN/SIMCA workflows and fitted models must not be assumed compatible:
  follow the recorded migration/refit requirements rather than changing
  serialized state by hand.
- PLS-DA distinguishes calibration fit, cross-validation and held-out evidence.
  Older PLS-DA/PCA/FastICA models may require refitting; eligible local exploratory
  application still requires explicit acknowledgement and does not qualify a model.
- Startup applies local database migrations, including the nullable project
  goal and goal-plan fields. Existing projects need not supply a goal.
- New PCA/PLS sample reviews require typed sample IDs. Anonymous historical data
  remain positional; readable display labels do not become verified identities.

### Saved export workflows

New Prepare Export nodes default to **CSV (plain)**. Choose **CSV (portable)**
or JSON for typed axes, units and metadata on reimport. A saved editable node
with historical `format: csv` must ask you to select plain or portable CSV
before preparing a new file: earlier builds used that value for both formats,
so the application cannot safely infer your intention. Save the selected format
with the workflow. Already-retained downloads are not rewritten.
