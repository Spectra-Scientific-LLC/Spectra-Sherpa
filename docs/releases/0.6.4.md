# SpectraSherpa 0.6.4

These notes describe SpectraSherpa 0.6.4. Source version alone does not
establish availability; check [PyPI](https://pypi.org/project/spectra-sherpa/).
Release receipts identify exact source revisions, artifact hashes and
qualification scope. Desktop packaging remains paused until separately authorized.

## Work with data

- [My Dataset portfolios](../workflows/data-import.md#build-a-portfolio-in-my-dataset)
  retain named selections, targets, groups and reviewed inclusion choices for
  reuse across workflow sheets. Sample identity is separate from editable labels.
- [Multi-well](../workflows/multi-well.md) supports 6-, 12-, 24-, 48-, 96-, 384-
  and 1536-well formats. Large plates pan without shrinking labels; acquisition
  plans and published measured-sample versions remain separate.
- Import, Upload, Library, Synthesis and Multi-well lead to My Dataset before
  Workflow. Storage recovery is under Settings.
- New Wine, Iris and Breast Cancer catalog imports carry typed observation IDs
  and separate readable sample labels. IDs identify source observations, not
  independent specimens; labels remain editable presentation text.
- Data Story uses parsed source facts and distinguishes acquisition settings
  from synthesis recipes. Starter, Data Story and chat can use an externally
  supplied API key in local OSS; the selected provider's policies and charges apply.

## Managed preprocessing and existing campaigns

Rubberband, Cosmic Ray Removal, Clip Feature Range and Clip Floor join the
managed optimization profile. They operate independently on each spectrum;
validation, full refit and canonical application use the same recorded nodes.
This advances the managed execution profile from 8 to 9.

Campaigns using supported historical profiles remain available for read-only
inspection, subject to retained-evidence verification. This includes the qualified
profile-8 predecessor. New rounds after a profile change require a new campaign
under the current qualified profile; existing campaigns
and recorded results are not rebound or relabelled. Before a hosted rollout, operators
must inventory started campaigns and communicate this continuation boundary.

Rubberband replaces the earlier local-only restriction (#642): its canonical
stateless execution is now qualified through managed validation/refit and
canonical application. This does not add legacy Load & Apply replay support.
PLS and PLS-DA autoscaling still refuse constant endpoint variables; new guaranteed-failing
proposals are rejected before trial admission. Separate Scale / Center already
handles constant variables safely and is not incorrectly prohibited.

## Analyze and inspect

- New PCA starters fit scaling inside PCA and each eligible validation fold.
  The preprocessing starter applies recorded sample inclusion through Filter.
  Existing workflows are not silently rewritten.
- Quick Plot and Detailed View share scientific projections and component
  controls. Tables and plots retain declared axes, units and population context;
  sampled or capped displays carry a visible **Subset** indicator.
- Runs uses consistent Summary, Results and Validation sections. Inspect links
  to the produced model; promotion review belongs under Models.
- Reopened clustering tables preserve source sample labels beside assignments.
  Hosted Advisor distinguishes executed settings from catalog defaults and exposes
  retained ICA reconstruction diagnostics as descriptive, not predictive, errors.
- Reports retain essential scientific qualifiers. Prepared exports distinguish
  plain CSV from portable CSV, support JSON, and package all processed spectra
  as individual JCAMP-DX files in a ZIP when JDX is selected.

### Saved source selections

Duplicated revision-backed workflow sheets receive their own selection revision
after current source, project and active-view admission. Original selection
receipts remain unchanged. Unbound sources stay unbound.

For registered sources with native responses and aligned annotation columns,
saved target selection verifies the original source before attaching selected
supervision. Native and table values must agree. This preserves the registered
identity; it does not authorize resealing a derived selection or admitting a
curated subset to canonical SDK application without separate subset authority.

## Reliability and presentation

Shared theme tokens cover controls, plots and offline reports. Categorical
palettes honor accessibility preferences; legacy server-built figures with
recorded explicit colors keep those colors. Scoped requests reject late replies
without clearing the workspace during same-account token renewal. Generated
API types, node reference tables and help-link checks reduce documentation drift.

Dependency security updates cover Python, frontend and optional tooling without
changing the qualified scikit-learn or SpectroChemPy scientific-runtime pins.
Source-level desktop dependency checks do not resume desktop packaging.

## Upgrading from the published 0.6.0 baseline

Back up the data directory and export important projects before upgrading.
Follow [Migrate to 0.6](../onboarding/migrate-to-0.6.md) for installation and
scientific-contract boundaries. For testing, install the exact reviewed source
or qualified artifact; use PyPI only after verifying that version is published. The retained saved-model compatibility reference
is **0.6.0**. Verify the public index before choosing any additional published
upgrade checkpoint; intervening source versions and release notes alone are
not evidence of PyPI availability. Retained 0.6.1–0.6.3 source installations
also need backed-up-profile migration checks.

- Review the intervening [0.6.1](0.6.1.md), [0.6.2](0.6.2.md) and
  [0.6.3](0.6.3.md) notes when upgrading directly from the earlier PyPI package.
  Older KNN/SIMCA workflows and fitted models must not be assumed compatible:
  follow the recorded migration/refit requirements rather than changing
  serialized state by hand. In particular, 0.6.0 tabular KNN/SIMCA models lack
  complete retained numeric feature identity and require retraining; guessing
  column order or editing model digests is not an upgrade path.
- PLS-DA distinguishes calibration fit, cross-validation and held-out evidence.
  Older PLS-DA/PCA/FastICA models may require refitting; eligible local exploratory
  application still requires explicit acknowledgement and does not qualify a model.
  Changed PLS-DA serializer or validation-semantics authority must be admitted
  explicitly or refused. Calibration diagnostics are not cross-validation or
  held-out performance; reconnect an explicit validation design when refitting.
- Startup applies local database migrations, including the nullable project
  goal and goal-plan fields. Existing projects need not supply a goal.
- New PCA/PLS sample reviews require typed sample IDs. Anonymous historical data
  remain positional; readable display labels do not become verified identities.

### Catalog IDs and diagnostic review compatibility

New PCA/PLS review receipts may carry readable labels, while selection, lookup
and requests retain full typed IDs. Older receipts without labels continue to
display their recorded IDs. The PLS-DA correction binds diagnostic rows to typed
observation IDs rather than labels; duplicate display labels are not duplicate
identities.

Existing files, fitted models and receipts are not rewritten or assigned new
identities. For an older source lacking typed IDs, attach an explicit sample
table or make a fresh catalog import and rerun the workflow; labels alone do
not repair identity. Applying affected existing models requires a reviewed
exact predecessor-to-consumer compatibility registration. Unrecognized
contracts remain refused. Historical campaign rounds cannot be replayed
under a changed profile.

### Saved export workflows

New Prepare Export nodes default to **CSV (plain)**. Choose **CSV (portable)**
or JSON for typed axes, units and metadata on reimport. A saved editable node
with historical `format: csv` must ask you to select plain or portable CSV
before preparing a new file: earlier builds used that value for both formats,
so the application cannot safely infer your intention. Save the selected format
with the workflow. Already-retained downloads are not rewritten.
